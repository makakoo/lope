## 1. Use Cases (`UC1`–`UC18`)

| ID | Use Case | Actors | Summary & Postcondition |
|---|---|---|---|
| **`UC1`** | **Drop-In CLI Health & Doctor Check** | User, `glimmer doctor` | Run `lope version`, `lope --version`, and `lope status` under a clean GUI `PATH` (`env -i`). Returns version `>= 0.17.3` (`2.0.0`), validator roster, and live manifest counts in `< 15ms`. |
| **`UC2`** | **Consensus File Review with Role Lens (`lope review`)** | Developer, Business Operator, Glimmer | Run `lope review <file> --consensus quorum --format markdown --focus <lens> --output <path>`. Fans out across validators, deduplicates and scores findings, writes clean Markdown to `<path>`, and exits `0`. |
| **`UC3`** | **Darwin Descendant-Safe Completion** | Validator CLI with background MCP helper | A validator CLI (`claude`, `codex`, `opencode`) prints its full response and exits `0`, leaving a child MCP server alive in its process group. Super Lope accepts the response immediately (`OutcomeClass::Ok`) and reaps the child group asynchronously without raising `cleanup_failed`. |
| **`UC4`** | **Automatic Blocker Remediation in PTY** | Validator CLI (`codex`, `claude`, `agy`) | Validator launched in a new worktree displays a `"Update available! Press enter to continue"` or `"Do you trust the contents of this directory?"` screen. `lope-detect` identifies the rule in `< 250ms`, sends the safe dismissal/trust keystroke, and completes the review without timing out. |
| **`UC5`** | **Fail-Fast on Unauthorized Tool/Auth Blocker** | Validator CLI in read-only `review` | During `lope review`, a misconfigured validator hits an interactive login prompt or asks permission to execute a mutating shell command (`live_strong_blocker`). Super Lope aborts that single validator in `< 250ms` with `OutcomeClass::Blocked(rule_id)` and completes consensus with the remaining validators. |
| **`UC6`** | **Warm Agent Pool Acceleration (`loped`)** | `loped` daemon, `lope ask` / `lope review` | With `lope daemon start` running, consecutive `lope ask` or `lope review` calls lease pre-warmed agent panes in `loped`, skipping Node.js/Python cold startup and returning first tokens in `< 500ms`. |
| **`UC7`** | **Multi-Model Q&A, Voting & A/B Comparison** | User, Agent Skill | Execute `lope ask "<prompt>"`, `lope vote "<question>" --options "A,B,C"`, `lope compare <fileA> <fileB> --criteria "<c>"`, and `cat diff.patch \| lope pipe`. Per-validator isolation ensures one failed validator never aborts the tally (unless `--require-all` is passed). |
| **`UC8`** | **Dynamic Team Management & `--from-curl`** | User, `lope-team` skill | Run `lope team list`, `lope team add`, `lope team remove`, `lope team test --timeout 10`, and `lope team add <name> --from-curl "<curl-cmd>"`. Updates `~/.lope/config.json` atomically with `0600` permissions. |
| **`UC9`** | **7-Stage Council Deliberation (`lope deliberate`)** | Architect, PM, Legal/Tax Advisor | Run `lope deliberate <scenario.md> --template {adr,prd,rfc,build-vs-buy,migration-plan,incident-review} --depth {quick,standard,deep}`. Executes intake, independent positions, anonymized `Response A/B/C` critique, revision, primary synthesis, rubric review, and minority report. |
| **`UC10`** | **Persistent Finding Memory (`lope memory`)** | Developer, Auditor | Store findings via `lope review --remember` into `~/.lope/memory.db` (Rusqlite + FTS5) and query via `lope memory {stats,search,file,hotspots,forget}`. |
| **`UC11`** | **Makakoo Brain Context & Journal Sync** | Makakoo OS (`Harvey`), Glimmer | Pass `--brain-context "<query>"` and `--brain-log` to `lope review` or `lope negotiate`. Queries `makakoo search`, injects redacted context within `--brain-budget`, appends a Logseq bullet to `$MAKAKOO_HOME/data/Brain/journals/YYYY_MM_DD.md`, and runs `makakoo sync`. |
| **`UC12`** | **Multi-Round Sprint Negotiation (`lope negotiate`)** | Developer, Business Operator, Researcher | Run `lope negotiate "<goal>" --domain {engineering,business,research} [--out <path>]`. Drafts and refines `SPRINT-<SLUG>.md` with domain-appropriate rubric sections and validator sign-off. |
| **`UC13`** | **Validator-in-the-Loop Sprint Execution (`lope execute` & `implement`)** | Developer, Glimmer Child Worktree | Run `lope implement <sprint-doc>` inside a child git worktree (or `lope execute <sprint-doc>`). For each phase: primary implements → objective gates run → ensemble validators review (`---VERDICT---`) → retry/heal on `NEEDS_FIX` → advance on `PASS`. |
| **`UC14`** | **Objective Verification Gates & Audit Scorecard (`lope gate`, `check`, `audit`)** | CI, Developer | Run shell/file verification gates (`lope gate`, `lope check`) and generate sprint execution scorecards (`lope audit`). |
| **`UC15`** | **Declarative DOT Flow Graph Execution (`lope flow`)** | Multi-Agent Architect | Run `lope flow {validate,render,run} <workflow.dot>`. Walks DAG/loop nodes (`agent`, `review`, `judge`, `script`) in parallel waves with blackboard state and strict `max_node_visits` budget caps. |
| **`UC16`** | **Live Split-Pane TUI Attach (`lope attach`)** | Interactive Operator | Run `lope attach [<run-id>]` while a Council review, deliberation, or sprint is running. Opens Herdr's Ratatui multi-pane TUI showing live terminal buffers, status badges, and keyboard/mouse focus to inspect or un-block any agent. |
| **`UC17`** | **Safe Stale Lease Pruning (`lope jobs prune --stale`)** | Glimmer Scheduled Panel, Operator | Inspect `~/.lope/state/sprints/`, verify process liveness via PID + start fingerprint + boot fingerprint, archive/prune dead leases, and leave active runs untouched. |
| **`UC18`** | **Remote SSH Validator Offload (`--machine`)** | Intel Mac User with `traylinx-ci` server | Configure or pass `--machine traylinx-ci` so heavy CLI validators execute in remote PTYs on the Hetzner server while returning structured verdicts to the local Mac. |

## 2. Verification Scenarios (`SC1`–`SC15`)

| Scenario | Description | Covered Use Cases | Verified In Sprint |
|---|---|---|---|
| **`SC1`** | **Clean GUI `PATH` & Glimmer Doctor Parity**: Under `env -i PATH="/usr/bin:/bin:/usr/sbin:/sbin:/usr/local/bin"`, `lope version`, `lope --version`, `lope status`, and `glimmer doctor` all exit `0`. | `UC1` | [`S0`](../sprints/S0-workspace-and-compat-cli.md), [`S8`](../sprints/S8-glimmer-cutover-and-benchmarks.md) |
| **`SC2`** | **Darwin Lingering-Child Reaping Test**: A synthetic validator prints a valid `---VERDICT---` block, spawns a background `sleep 30` child in its process group, and exits `0`. Super Lope returns the valid `PASS` verdict in `< 300ms` and kills the background child asynchronously. | `UC3` | [`S1`](../sprints/S1-pty-supervisor-and-detector.md) |
| **`SC3`** | **Interactive Blocker Auto-Remediation (`trust_directory` & `startup_update`)**: A synthetic PTY agent renders the exact `codex.toml` `"Update available!"` screen followed by `"Do you trust the contents of this directory?"`. Super Lope detects both in `< 250ms`, sends `Enter`, and captures the final answer. | `UC4` | [`S1`](../sprints/S1-pty-supervisor-and-detector.md), [`S2`](../sprints/S2-warm-pool-and-daemon.md) |
| **`SC4`** | **Read-Only Review Permission Blocker Fail-Fast**: During `lope review`, one validator renders `claude.toml` `live_blocked_form` asking to run `rm -rf`. Super Lope aborts that validator in `< 250ms` as `Blocked(live_blocked_form)` and completes consensus using the remaining validators. | `UC5` | [`S1`](../sprints/S1-pty-supervisor-and-detector.md), [`S4`](../sprints/S4-single-shot-and-consensus-review.md) |
| **`SC5`** | **Warm Pool Cold-Start Elimination**: Start `loped`, warm 2 agent panes, and run 3 sequential `lope ask` calls. Call 2 and Call 3 dispatch into the warm panes with `< 50ms` local dispatch overhead. | `UC6` | [`S2`](../sprints/S2-warm-pool-and-daemon.md) |
| **`SC6`** | **`--from-curl` Provider Registration & Native HTTP Fan-Out**: Register a local mock HTTP server via `lope team add local-mock --from-curl "curl ..."`, run `lope team test local-mock`, and execute `lope ask` + `lope vote`. | `UC7`, `UC8` | [`S3`](../sprints/S3-validators-and-http-engine.md) |
| **`SC7`** | **Glimmer Watched Council Review & Role Lenses**: Run `lope review <notes.md> --consensus quorum --format markdown --focus tax --output /tmp/report.md`. Verify UTF-8 Markdown file creation, deduplicated findings, and SARIF output (`--format sarif`). | `UC2` | [`S4`](../sprints/S4-single-shot-and-consensus-review.md), [`S8`](../sprints/S8-glimmer-cutover-and-benchmarks.md) |
| **`SC8`** | **Finding Memory Persistence & Makakoo Brain Round-Trip**: Run `lope review <file> --remember --brain-context "Harvey" --brain-log`. Verify finding lands in `~/.lope/memory.db` (`lope memory search`), context block is prepended once, and bullet lands in today's Makakoo journal + FTS5 index. | `UC10`, `UC11` | [`S5`](../sprints/S5-memory-and-makakoo-bridge.md) |
| **`SC9`** | **7-Stage ADR Council Deliberation with Anonymized Critique**: Run `lope deliberate scenario.md --template adr --depth standard --output adr-out.md`. Verify all 7 stages execute, peer critiques use anonymized `Response A/B/C` labels, and `NEEDS_FIX` objections appear in the Minority Report section. | `UC9` | [`S6`](../sprints/S6-council-deliberation.md) |
| **`SC10`** | **Live TUI Attach During Deliberation (`lope attach`)**: Launch a deliberation in the background, attach via `lope attach` in a headless/virtual terminal test harness, verify split panes render each validator's buffer and status badge, and detach cleanly with `Ctrl+B q`. | `UC16` | [`S6`](../sprints/S6-council-deliberation.md) |
| **`SC11`** | **Domain Sprint Negotiation (`engineering` & `business`)**: Run `lope negotiate "Add invoice QR validator" --domain business --out /tmp/SPRINT-QR.md` and verify `Deliverables` and `Success Metrics` sections are generated. | `UC12` | [`S7`](../sprints/S7-sprints-and-flow-graphs.md) |
| **`SC12`** | **Child-Worktree Sprint Implementation with Retry**: Run `lope implement /tmp/SPRINT-QR.md` in an isolated git worktree where Phase 1 initially returns `NEEDS_FIX` then `PASS` on retry 1. Verify phase advances and `lope audit` reports `PASS`. | `UC13`, `UC14` | [`S7`](../sprints/S7-sprints-and-flow-graphs.md) |
| **`SC13`** | **Declarative DOT Flow Graph with Loop & Visit Cap**: Execute a `.dot` flow graph containing a `propose -> review -> fix` back-edge loop. Verify conditional routing works and an infinite-loop graph terminates deterministically at `max_node_visits`. | `UC15` | [`S7`](../sprints/S7-sprints-and-flow-graphs.md) |
| **`SC14`** | **Stale Manifest Reconciliation & Pruning**: Seed `~/.lope/state/sprints/` with 3 dead-PID manifests and 1 live-PID manifest. Run `lope jobs prune --stale`. Verify the 3 dead manifests are archived/pruned and the 1 live manifest is untouched. | `UC17` | [`S1`](../sprints/S1-pty-supervisor-and-detector.md), [`S8`](../sprints/S8-glimmer-cutover-and-benchmarks.md) |
| **`SC15`** | **Intel Mac Resource & Latency Benchmark (`Python Lope` vs `Super Lope`)**: Benchmark startup latency (`lope version`), 5-validator parallel fan-out memory RSS, and CPU time on the dogfood Intel Mac (`i5-8257U`). Verify `< 10ms` startup and `< 25 MB` RSS. | `UC1`, `UC2`, `UC6` | [`S8`](../sprints/S8-glimmer-cutover-and-benchmarks.md) |
